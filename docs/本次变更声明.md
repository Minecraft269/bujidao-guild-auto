# 变更声明 — 2026-10-11 完全推倒重写轮次

**范围**：建立公开仓库 + Git 基线存档 + CI 流水线 + 按流程规格重写脚本本体
**前提**：`v1.0-legacy` 永久保留重写前的完整实现，任何时候可用 `git checkout v1.0-legacy` 回到旧版
（本文是本轮新档；2026-08 那份《更改声明.md》保留作为历史记录。）

---

## 一、为什么改（本轮动机）

### 1. 旧实现的异步语义与需求相反

旧实现的"异步"是：主线程把 (命令, 验证函数) 投给后台 worker，然后调
`_join_with_progress` 等它跑完，最后 `get_result_nowait` 取回结果。
验证函数内部仍然调用 `send_and_capture` → `wait_for_chat_block`。

**问题**：主线程虽然"提交后不立即阻塞"，但它随后就开始等待结果，
发送节奏被后台验证速度拖住——没有达到需求描述的核心价值：

> 「异步系统用于更快地发送指令;主线程不验证、不读取、不解析,全靠异步系统返回结果。」

### 2. `main()` 是 640 行的巨型函数，不可测

它在函数体内直接调 `pyautogui` / `ctypes` / `input()` / `os.path`，
硬件依赖与流程编排缠死。结果是 `main.py` 覆盖率只有 8%，
而它占了项目总体覆盖率缺口的 95%——总体门禁（≥85%）无论如何都过不去。

### 3. 项目没有版本控制与 CI

无 git、无公开仓库、无自动化验证。改一行都可能悄悄破坏业务规则
（阈值/文案/命令格式），没有任何东西能拦住。

## 二、改了什么

### 1. 仓库与基线（阶段 0）

- `git init` 于 `guild_auto_v2/`（仓库根 = 脚本本体）
- **脱敏**后提交基线，打 tag `v1.0-legacy` 永久保存重写前的完整实现
- 创建公开仓库并推送

**脱敏明细**（公开仓库铁律）：

| 项 | 处理 |
|---|---|
| `config.py` 硬编码 QQ 群号 | → 占位符 `YOUR_QQ_GROUP` |
| `config.py` 管理员名 | → 空字符串（留空则运行时自动识别） |
| `D:\MCLDownload\...` 本地绝对路径 | → 占位符 `C:\Path\To\Minecraft\logs\latest.log` |
| `config.json`（用户实际配置） | 不入库，写进 `.gitignore` |
| `tests/samples/*.txt` 真实玩家 ID | → 合成样本（演示公会 / 演示玩家甲） |
| `test_e2e_real_log.py` 真实日志路径 | → 改环境变量 `GUILD_TEST_GAME_LOG` 注入，未设则 skip |
| `reports/` `logs/` 真实产物 | 不入库 |

`.gitignore` 只写"所有人都适用"的忽略项；`.omc/`、`.remember/`、`.memory/`、`.claude/`
这些个人目录**不写入** `.gitignore`，改由本地 `.git/info/exclude` 忽略。

### 2. CI 流水线（阶段 1，4 条）

| 流水线 | 内容 | 状态 |
|---|---|---|
| `lint.yml` | ruff（line-length 100，规则集 `E9/F/A/TC/ICN/ISC/RSE/TID`） | ✅ 绿 |
| `test.yml` | pytest + **双档覆盖率门禁**，Python 矩阵 3.10/3.11/3.12 | ⚠ core 过 / overall 待 main 重写 |
| `build.yml` | PyInstaller（onefile + UPX + 14 个 `--exclude-module`）→ artifact → tag 时 Release | ✅ 绿（19.94 MB） |
| `security.yml` | CodeQL + dependency-review + pip-audit | ✅ 绿 |

**双档门禁是这样实现的**：两次独立 coverage 运行、独立数据文件、独立报告。

```powershell
# Gate 1: 核心层 ≥95%
COVERAGE_FILE=.coverage.core python -m pytest tests `
  --cov=parsers --cov=actions --cov=config --cov=reporter --cov=async_system `
  --cov-fail-under=95

# Gate 2: 总体 ≥85%（排除规则写在 .coveragerc，经 COVERAGE_RCFILE 指入）
COVERAGE_FILE=.coverage.total COVERAGE_RCFILE=.coveragerc python -m pytest tests `
  --cov=. --cov-fail-under=85
```

两次都过才算绿。核心层用**显式列模块**而非 include 文件，避免把待翻转的旧执行器
算进核心门禁。

### 3. 新增模块：`async_system.py`（异步后台验证系统）

这是本轮架构翻转的核心。语义与旧 `async_executor.py` **相反**：

| | `async_executor.py`（旧） | `async_system.py`（新） |
|---|---|---|
| 发送 | 后台 worker 逐条发 | 后台发送线程逐条发 |
| 验证 | 主线程投 verify，后台跑，主线程 `join` 等 | **后台独立验证线程**，主线程完全不参与 |
| 主线程职责 | 提交 + 等结果 + 取回 | **只提交**；全部工作完成后才 `wait_all` |
| 失败处理 | 后台重试 + 补做队列 | 记录结果等主线程决策，重试由主线程发起的下一轮驱动 |
| 完成信号 | `queue.join()` | `_all_done` Event（主线程 `wait_all` 带总超时） |

状态机：`PENDING → SENT → OK(抛弃) / FAILED(记录等重试) → STOPPED(补做)`。

### 4. 模块重写与职责分离

| 模块 | 变化 |
|---|---|
| `actions.py` | 瘦身为**纯决策层**：`decide_actions` / `new_rank_after` / `build_notification` / `build_command`，**不再 import pyautogui** |
| `action_executor.py` | **新增**。`ActionExecutor`（发送/暂停门/回显检测/重试/广播）搬到这里，硬件执行与业务决策彻底分离 |
| `parsers.py` | 重写，解析边界更严谨 |
| `logger.py` | 重写，6 级日志；追踪级覆盖函数调用链/文件读写/执行位置/线程队列/后台验证全过程 |
| `config.py` | 重写，`validate_config` 增强（必需键、三组延时区间、阈值逻辑一致性、game_log 防呆） |

## 四、修掉的缺陷（测试暴露的真实问题，非猜测）

| # | 缺陷 | 后果 | 修复 |
|---|---|---|---|
| 1 | `async_system._all_tasks_terminal()` 对**空任务集**返回 True | 验证线程在启动瞬间（尚无任务）就 `return`，之后 submit 的任务**永远无人验证** | 空集必须返回 False |
| 2 | `wait_all()` 完成条件误设为「全部 OK」 | 一个永远失败的任务让每轮空等到超时（实测 3 轮 **12s**，修后 **0.06s**） | 完成条件改为「没有 PENDING/SENT」——FAILED 是已完成的验证结果 |
| 3 | 多轮重试结果重复计数 | 同一指令被算成"成功 1 条 + 失败 2 条" | 按 `(command, player)` 业务键去重；已归档任务移出 `_tasks` |
| 4 | `new_rank_after` 对未知动作名落进 promote 分支 | 配置写错时**误报玩家新等级**，掩盖异常 | 只认 promote/demote/kick，其余保守返回原等级 |
| 5 | `validate_config` 遇到非数字延时直接 `TypeError` | 校验器自己先崩，用户看不到"配置写错了"的提示 | 数值比较前做类型守卫 |
| 6 | CI 用了 `--cov-omit`（不是 pytest-cov 合法参数） | 覆盖率门禁命令直接报错退出，**门禁形同虚设** | 改用 `.coveragerc` + `COVERAGE_RCFILE` |
| 7 | `Build` 触发器只有 `tags` + `pull_request` | 自家仓库 push 到 main 不产生 PR 事件 → Build **从创建起零运行** | 改为 `push: branches: ['**']`；Release 仍由 tag 守卫 |
| 8 | `pip-audit` 步骤缺 UTF-8 环境变量 | Windows runner 是 cp1252 管道，输出中文漏洞描述时 `UnicodeDecodeError` 把 job 打死（不是漏洞，是编码） | 加 `PYTHONIOENCODING=utf-8` + `PYTHONUTF8=1` |
| 9 | `FakeImage.save(self, buf, format=None)` 触发 ruff A002 | Lint 由绿转红 | 加行内 noqa——参数名必须与 PIL 真实签名一致，改名会让 mock 失真 |
