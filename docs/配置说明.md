# 配置文件说明(config.json)

> 首次运行 `python -m guild_auto` 时自动生成 `config.json`;修改后保存,重启脚本生效。
> 所有业务规则默认值**继承自原脚本**(阈值/文案/命令格式),不建议改动数值;除配置文件默认值外,代码中无任何硬编码业务参数。
> 命令行参数 `--admin/--log/--options` 可临时覆盖对应项,不改动文件。

## 人员信息

| 键 | 类型 | 默认值 | 说明与取值范围 |
|---|---|---|---|
| `admin` | string | `""` | 管理员名(当前执行操作的人),用于报告与通知标注。留空=启动时自动从游戏日志 `--username, <ID>` 启动参数识别;填写后以填写值为准。示例:`"演示管理员"` |
| `guild_qq` | string | `"YOUR_QQ_GROUP"` | 公会 QQ 群号,出现在通知文案尾部"公会群:xx"。原脚本硬编码值,继承 |

## 黑白名单与屏蔽词(阶段 5)

名字匹配**始终大小写不敏感**;`match_wildcard` 为 true 时额外支持 `*` 与 `?`。

优先级(短路,先命中先返回):

```
功能开关(promote/demote/kick enabled)
  > blacklist            → 完全不处理(不查询/不通知/不升降踢)
  > 屏蔽词策略            → 名字被网易过滤成星号,不发送查询指令
  > whitelist(非空)       → 只处理名单内的人
  > whitelist_protected   → 免降职/踢出(升职仍生效)
  > 阈值判定(继承原脚本,零改动)
```

| 键 | 类型 | 默认 | 作用与可填值 |
|---|---|---|---|
| `blacklist` | array | `[]` | 黑名单:名单内玩家**完全不处理**。可填名字或通配模式(如 `["捣乱玩家"]`、`["测试*"]`) |
| `whitelist` | array | `[]` | 白名单:非空时**只有**名单内玩家参与升降踢判定;留空表示不启用 |
| `whitelist_protected` | array | `[]` | 保护名单:免降职与踢出,升职仍生效。适合保护新人/管理小号 |
| `match_wildcard` | bool | `true` | 是否启用 `*`/`?` 通配。false 时只做精确匹配(星号当普通字符) |
| `blocked_name_policy` | string | `"skip"` | 屏蔽词玩家策略:`skip`=不发送 `/guild member ***` 指令(默认,推荐);`query_attempt`=仍尝试(通常超时浪费重试,仅调试) |

> 屏蔽词玩家的名字被网易替换为整串 `*`,身份不可读。脚本**不发送**查询指令,
> 直接记为 blocked,并在报告里单列为「屏蔽词玩家(指令不可查)」,需人工确认。

## 超时与重试(秒)

| 键 | 默认值 | 说明与取值范围 |
|---|---|---|

## 自定义规则（阶段 4）

| 键 | 类型 | 默认 | 作用与可填值 |
|---|---|---|---|
| `rules_enabled` | bool | `false` | 是否启用规则引擎。`false`=只用内置阈值规则；`true`=按 `rules` 判定，**内置阈值规则作为其中一条默认规则**参与（同一接口） |
| `rules_strategy` | string | `"first_match"` | 多规则命中时：`first_match`=列表顺序首个命中；`highest_priority`=priority 最大者；`all`=全部命中 |
| `rules` | array | `[]` | 规则列表，见下方结构 |

**单条规则结构**

```jsonc
{
  "id": "r1",                 // 唯一，报告用它追溯"命中哪条规则"
  "name": "低贡献降职",
  "enabled": true,
  "priority": 100,            // 越大越优先（highest_priority 策略用）
  "stop": true,               // 命中后是否停止匹配后续规则
  "conditions": [ {"field": "weekly_total", "op": "<", "value": 1000} ],
  "actions":    [ {"type": "demote", "times": 1} ]
}
```

**可用条件**（多个条件之间是 AND；读不到一律判否，绝不当 0）

| field | 可用 op | 说明 |
|---|---|---|
| `weekly_total` | `<` `<=` `>` `>=` `==` | 周贡献（数值） |
| `rank` | `==` `!=` `in` `not_in` | 等级键（entry/low/mid/high） |
| `online` | `==` `!=` | 在线状态（true/false；读不到不算命中） |
| `player` | `==` `!=` `matches` | `matches` 支持 `*` `?`，大小写不敏感 |
| `joined_at` / `last_online` | `before` `after` | 日期 `YYYY-MM-DD[ HH:MM:SS]` |

**可用动作**：`promote(times)` / `demote(times)` / `kick(reason)` / `notify` / `ignore`

**优先级**：功能开关 > 黑名单 > 屏蔽词策略 > 白名单 > 保护名单 > **规则/阈值判定**。
即：关闭 `kick_enabled` 后，任何规则里的踢出动作都不会执行（串行与异步两条路径都已强制）。

**校验**：`rules_enabled=true` 时启动即校验规则语法，错误会指明「哪条规则的哪个字段」并退出（不静默兜底）。

## 日志系统

日志写入脚本同目录的 `logs/` 文件夹（自动创建）：

- `latest.log` —— 本次运行进行中的最新日志
- `app-YYYY-MM-DD.gz` —— 历史归档：每次启动时把上一次的 `latest.log` 重命名为 `app-YYYY-MM-DD.log` 后压缩成 `.gz` 压缩包（压缩包内即该 `.log` 文件）；同一天多次运行时文件名末加序号防重复（`app-2026-08-21.gz`、`app-2026-08-21-2.gz`、`app-2026-08-21-3.gz` …）

| 键 | 类型 | 默认值 | 说明 |
|---|---|---|---|
| `log.enabled` | bool | `true` | 是否启用日志文件（`false`=不写文件，控制台输出不受影响） |
| `log.level` | integer | `4` | 日志级别：数字越大越详细，**每一级包含上一级（更严重）的全部**。`1`=致命（仅脚本启动失败/意外关闭）`2`=严重错误 `3`=错误 `4`=信息（默认）`5`=调试 `6`=追踪（最详细） |
| `log.dir` | string | `"logs"` | 日志目录（相对脚本运行目录，自动创建） |

> 取值范围：`log.level` 为 1~6 的整数；控制台始终打印全部信息，日志文件按级别过滤。
> 用户手动中断（Ctrl+C）记为"信息"级；意外崩溃/启动失败记为"致命"级（任何级别下都会记录）。

## 操作模式（阶段 6）

| 键 | 默认 | 说明 |
|---|---|---|
| `operation_mode` | `"command"` | `command` = 指令模式（发 `/guild` 命令 + 读日志验证）；`ui` = UI 识别模式（截图 OCR + 界面操作）。选 `ui` 时当前构建必须含 `vision` 能力，否则启动即报错，不会静默退回指令模式。 |

## UI 识别参数 `vision`

仅在 `operation_mode="ui"` 时生效。**所有键位都从 `game_options` 指向的 options.txt 运行时读取**，代码里没有任何默认键值。

| 键 | 默认 | 作用 / 可填值 |
|---|---|---|
| `vision.hotbar_slot` | `7` | 「装备与个人设定」所在快捷栏槽位，1~9。实际按键由 `options.txt` 的 `key_key.hotbar.<槽位>` 决定。 |
| `vision.stay_ms` | `120` | 扫掠每个停留点等 tooltip 渲染的毫秒数。不得小于 120（太短会漏数据）；机器慢可调 200~300。 |
| `vision.sweep_gap_ratio` | `1.0` | 扫掠步长比例 (0,1]。1.0=按整格步进；小于 1 为重叠扫描（更慢更稳）；大于 1 会漏格。 |
| `vision.low_confidence` | `0.7` | OCR 置信度门槛 0~1。低于门槛的停留点会二次确认或重扫。 |
| `vision.max_misclick` | `3` | 连续误按阈值（≥1）。超过后按 Esc 回退并重新全扫。 |
| `vision.kick_verify` | `"any"` | 踢出交叉验证方式：`grid`=格位消失 / `count`=人数 N→N-1 / `time_window`=时间窗 / `any`=任一成立。**不得单凭「踢出成功」归因**；都不成立时标「执行结果待确认」。 |
| `vision.ocr_command` | `""` | 外部 OCR 命令模板（可选）。未安装 pytesseract 时，UI 模式需要它；`{image}` 为截图临时文件路径。留空且无 pytesseract → 启动报错，不静默降级。 |
| `vision.grid.*` | 见下 | 扫掠网格（像素坐标，需按实际分辨率标定）。 |

`vision.grid` 子键：

| 键 | 默认 | 说明 |
|---|---|---|
| `origin_x` / `origin_y` | `0` | 物品区左上角像素坐标（≥0） |
| `cell_width` / `cell_height` | `36` | 单个格子宽/高（≥1），扫掠步长 = 该值 × `sweep_gap_ratio` |
| `columns` / `rows` | `9` / `6` | 格子列数/行数（≥1） |
| `expected_cells` | `54` | 预期物品格数；扫掠结束后与实际识别到语义的格数对账，缺口超阈值判定不完整并要求重扫 |
| `max_missing_ratio` | `0.0` | 允许的缺口比例 [0,1]。0=一格都不许漏；界面空槽多时可放宽（如 0.2），越宽越可能漏掉真实成员 |

## UI 模式自动暂停 `pause`

仅 `operation_mode="ui"` 且执行中生效；阶段确认等待、空闲、指令模式、按暂停键本身都不触发。

| 键 | 默认 | 说明 |
|---|---|---|
| `pause.auto_on_user_input` | `true` | 执行中检测到用户键盘按键/鼠标移动/点击是否自动暂停。`false` = 只能手动按暂停键。 |
| `pause.user_input_grace_ms` | `300` | 脚本自己模拟输入后的忽略窗口（毫秒，≥0）。脚本按键/移动会在此期间屏蔽监听，避免自己触发自己。输入设备慢可调大到 500。 |

暂停后只提示、不继续；**仅暂停键**可解除，继续后会重置窗口并重新全扫确认界面。

## 异步执行 `async`

| 键 | 默认 | 说明 |
|---|---|---|
| `async.enabled` | `false` | `true` = 异步模式（主线程只发不验，后台线程读日志验证）；`false` = 串行（逐条发送并立即验证，排障建议用它）。 |
| `async.num_workers` | `1` | 后台验证线程数（≥1）。注意：**发送始终串行**（共用发送锁），并发的只是"等待与验证"。 |
| `async.max_queue_size` | `100` | 命令队列容量（≥1）；满了会阻塞提交而不是静默丢弃。 |
| `async.max_retries` | `3` | 单条命令验证失败的最大重试次数（建议 1~5）；耗尽后进入失败清单并写入待办。 |
| `async.retry_delay` | `1.0` | 两轮重试之间的等待秒数（建议 0.5~3）。 |
