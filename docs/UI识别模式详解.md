# UI 识别模式详解

> 本文档依据 `screen/` 下 **31 张实拍截图**逐张核对后写成，描述游戏 UI 的真实结构，
> 是 `plan.txt`【阶段 6】的实现细则。
>
> ⚠ 截图仅用于理解结构，**不得作为图标模板匹配的素材**（材质包会改变全部图标外观）。

---

## 一、界面层级与入口链

```
大厅
 └─ 按 hotbar.7 对应的键（默认 key.keyboard.x，从 options.txt 读 key_key.hotbar.7）
    → 选中装备栏第 7 格「装备与个人设定」→ 使用
    → 【装扮与个人设定】界面（标题即此名）
       └─ 找「公会」物品（minecraft:painting，tooltip 含「公会 / Guilds / 点击使用」）
          → 点击使用
          → 【公会系统】界面（成员列表，物品格子）
             ├─ 悬停成员头像 → 成员 tooltip（完整数据）
             ├─ 点击成员头像 → 【<玩家名>】成员详情界面
             │    ├─ 升职物品（diamond_helmet）
             │    ├─ 降职物品（golden_helmet）
             │    ├─ 踢出物品（barrier）→ 点击 → 【确认界面】
             │    │      ├─ 确认（red_terracotta）→ 执行并关闭界面
             │    │      └─ 返回（white_terracotta）→ 回到成员详情
             │    └─ 返回公会界面（spectral_arrow）
             ├─ 公会详情（minecraft:book）→ tooltip 含「人数: [N/M]」
             ├─ 上一页（tipped_arrow）/ 下一页（arrow）
             └─ （无关物品：minecraft:diamond = 组队功能）
```

### 界面标题是可靠的定位锚点

| 标题 | 含义 |
|---|---|
| `装扮与个人设定` | 个人设置界面 |
| `公会系统` | 成员列表界面 |
| `<玩家名>` | **成员详情界面**（标题就是该玩家名） |
| `确认界面` | 二次确认界面（删/踢类操作） |
| `********` / 全星号 | 屏蔽词玩家的详情界面 |

> **实现建议**：用标题文字判断"当前在哪个界面"，比识别格子内容更快更稳。

## 二、公会系统界面 = 物品格子

界面主体是**背包样式的物品格子**，所有功能都是格子里的物品。**同格混有无关物品**。

| 物品 ID | tooltip 关键文字 | 作用 | 必需 |
|---|---|---|---|
| `minecraft:player_head` | 成员名 + 在线状态/公会身份/首次加入/上次在线/周贡献/每日明细 | **一个成员** | ✅ 核心数据源 |
| `minecraft:tipped_arrow` | 「上一页」 | 上一页 | ✅ |
| `minecraft:arrow` | 「下一页」 | 下一页 | ✅ |
| `minecraft:spectral_arrow` | 「返回公会界面」 | 返回上级 | ✅ |
| `minecraft:book` | 「公会详情 / 名称 / 会长 / **人数: [N/M]** / 今日经验」 | 取成员总数 | ✅ |
| `minecraft:diamond` | 「发起组队 / 邀请<玩家名>一起组队」 | **组队功能** | ❌ **无关，必须排除** |

> ⚠ **关键风险**：格子里有无关物品。**禁止按位置盲点**，
> 每次操作前必须先悬停读 tooltip 文字确认语义。

### 成员详情界面内的物品

| 物品 ID | tooltip 关键文字 | 作用 |
|---|---|---|
| `minecraft:diamond_helmet` | 「升职 / 升职玩家的公会职位」 | 升职该成员 |
| `minecraft:golden_helmet` | 「降职 / 降职玩家的公会职位」 | 降职该成员 |
| `minecraft:barrier` | 「踢出<玩家名> / 所有操作将会被记录 / 请谨慎操作！」 | 踢出该成员 |

### 确认界面的物品

| 物品 ID | tooltip 关键文字 | 作用 |
|---|---|---|
| `minecraft:red_terracotta` | 「确认 / 请确定您要踢出此用户 / 点击确认」 | 执行 |
| `minecraft:white_terracotta` | 「返回 / 点击返回」 | 放弃并返回 |

## 三、成员 tooltip（核心数据源）

悬停成员头像后显示，**与指令模式 `/guild member` 面板信息量等同**：

```
<玩家名>
在线状态: ●
公会身份: 中等活跃成员
首次加入: 2026-09-26 21:38:03
上次在线: 2026-10-25 19:55:27(2.75天前)
公会经验周贡献: 6,799 公会经验
    今天          : 0 公会经验
    2026-10-27: 0 公会经验
    2026-10-26: 0 公会经验
    2026-10-25: 564 公会经验
    2026-10-24: 1,310 公会经验
    2026-10-23: 4,925 公会经验
    2026-10-22: 0 公会经验
minecraft:player_head
```

### 字段解析要点

| 字段 | 要点 |
|---|---|
| 玩家名 | 首行；屏蔽词玩家显示为全星号 |
| 在线状态 | **圆点颜色**（绿=在线/红=离线）。OCR 只读到「●」，**必须配合像素颜色采样** |
| 公会身份 | 即等级 |
| 首次加入 | 对应指令模式的「加入时间」 |
| 上次在线 | 绝对时间 + 括号内相对时间，两者都要能解析 |
| 公会经验周贡献 | 合计值，**含千分位逗号**（6,799） |
| 每日明细 | 7 行，「今天」行必须在列（周贡献包含今天） |

### 与指令模式数据对照

| 数据 | 指令模式 | UI 模式 |
|---|---|---|
| 姓名 | ✅ | ✅（屏蔽词除外） |
| **在线状态** | ❌ **无** | ✅ **UI 独有** |
| 等级 / 首次加入 / 上次在线 / 周贡献 / 每日明细 | ✅ | ✅ |

> **结论：UI 模式不是信息降级方案，数据等同且多一个「当前在线状态」。**

## 四、操作结果验证（⚠ 三种操作的回显不同）

操作后结果回显到**聊天栏**，可从 `latest.log` 读到 —— 因此 **UI 模式可复用 `log_watcher` 做结果验证**。

| 操作 | 聊天回显 | 含玩家名？ | 验证策略 |
|---|---|---|---|
| **升职** | `成功设置<玩家名>的职位为<新等级>!` | ✅ **含** | 按玩家名 + 新等级匹配 |
| **降职** | `成功设置<玩家名>的职位为<新等级>!` | ✅ **含** | 同上 |
| **踢出** | `踢出成功` | ❌ **不含** | **不可用名字匹配**（见下） |
| 权限不足 | `你只能修改低于自己职位的公会成员职位!` | ❌ | 视为失败并告警 |

### 踢出的验证策略（因为回显不含玩家名）

可选其一或组合：

1. **串行单踢 + 界面确认**：一次只踢一人，踢完回到公会系统界面重新全扫，确认该格位（成员）消失
2. **数量对账**：踢前记录「人数: [N/M]」，踢后复查 N-1；累计踢出数与 N 的减少量一致
3. **时间窗匹配**：踢出前后记录日志时间戳，只接受紧邻本次操作后的那条「踢出成功」
   —— 仅在前两种不可用时作为兜底，且必须串行执行避免歧义

**纪律**：不得把「踢出成功」直接归因到最近操作的玩家而不做交叉验证；宁可标记「执行结果待确认」。

## 五、屏蔽词玩家

- **成员详情界面**（标题为全星号）：tooltip 数据**完整可读**（姓名仍屏蔽，但状态/身份/加入/上次在线/周贡献/每日明细全在）
  → **可按格位正常判定与操作，不因屏蔽词放弃处理**
- **踢出确认界面**：tooltip 只显示警告文案，不含成员数据
- **纪律**：字段读不到时**必须标「不可读」**，**严禁当作 0** —— 这是「数据缺失伪装零贡献」bug 的翻版

## 六、公会详情（取成员总数）

悬停 `minecraft:book`：

```
公会详情
名称: <公会名>
会长: <会长名>
描述: ...
标签: [<标签>]
人数: [280/280]        ← 当前人数 / 上限 = 成员总数
今日经验: 28,975
minecraft:book
```

- **成员总数** = `人数: [N/M]` 中的 N
- 界面**不显示在线成员数** → 遍历所有成员 tooltip，按在线状态圆点颜色累计
- tooltip 不可得 → 退回「逐页成员计数累计」，并在报告注明来源

## 七、翻页与导航

| 动作 | 物品 | 识别方式 |
|---|---|---|
| 下一页 | `minecraft:arrow`，tooltip「下一页」 | tooltip 文字 |
| 上一页 | `minecraft:tipped_arrow`，tooltip「上一页」 | tooltip 文字 |
| 返回公会界面 | `minecraft:spectral_arrow`，tooltip「返回公会界面」 | tooltip 文字 |
| 确认界面返回 | `minecraft:white_terracotta`，tooltip「返回」 | tooltip 文字 |

**纪律**：
- 每次翻页/返回后**必须重新全扫**确认当前界面与页码，禁止凭记忆断言
- 用**界面标题**快速判定所处界面
- 末页判定后回翻至首页，避免残留状态

## 八、按键试探（hotbar）

```
1. 从 options.txt 解析 key_key.hotbar.7 → 候选键（如 key.keyboard.x）
2. 按首选键 → 等渲染（≥300ms）→ 截图 + 全扫标题
3. 判断标题是否为「装扮与个人设定」
   是 → 缓存该键，本次会话复用
   否 → 记失败，取候选键列表下一项，回 2
4. 候选耗尽 → 暂停提示人工介入，或按配置降级为指令模式
5. 连续误按超阈值 → Esc 回退到干净状态后重新全扫
```

**防御**：每次按键后必须截图确认，禁止假设生效；误按后不得在错误界面继续乱点。

## 九、材质包兼容性

实拍对照（原版 / 第三方材质包 / 服务器材质包，共 10 张）：

| 项 | 是否随材质包变化 |
|---|---|
| **格子布局与坐标** | ❌ 不变（完全一致） |
| **界面标题文字** | ❌ 不变 |
| **tooltip 文字内容** | ❌ 不变（服务器下发，与材质包无关） |
| **图标外观** | ✅ 全部改变 |
| **物品模型** | ⚠ **部分材质包可能改变模型**（不确定，需防御） |

**结论**：
- ✅ 位置导航可行（格子坐标稳定）
- ❌ 图标模板匹配不可行
- ✅ **tooltip 文字 + 界面标题是唯一稳定的识别锚点**
- ⚠ 因模型可能被改，定位不得依赖物品的视觉形状

## 十、边界与错误情况

| 情况 | 表现 | 处理 |
|---|---|---|
| 权限不足 | 聊天「你只能修改低于自己职位的公会成员职位!」 | 标为失败并告警；该玩家应已被 `skip_ranks` 排除，出现即说明名单配置有误 |
| 踢出回显无玩家名 | 聊天仅「踢出成功」 | 见第四节验证策略 |
| 屏蔽词玩家 | 标题/姓名全星号 | 按格位操作，数据照读 |
| tooltip 字段缺失 | 某些界面只显示部分行 | 标「不可读」，禁止当 0 |
| 组队钻石误点 | 会把成员拉进队伍 | **必须靠 tooltip 文字排除**，禁止盲点 |

## 十一、实现约束汇总

| # | 约束 | 原因 |
|---|---|---|
| 1 | 禁止图标模板匹配 / 像素比对 | 材质包改变全部图标，模型也可能变 |
| 2 | 必须全屏 OCR + 文字语义定位 | tooltip 文字与界面标题是唯一稳定锚点 |
| 3 | 禁止按位置盲点 | 格子混有无关物品（组队钻石） |
| 4 | 每次按键/点击后截图确认 | 不能假设操作生效 |
| 5 | 每次导航后重新全扫 | 不能凭记忆断言界面 |
| 6 | 在线状态需像素颜色采样 | OCR 只读到「●」，颜色才是语义 |
| 7 | 缺失字段标「不可读」，禁止当 0 | 防「数据缺失伪装零贡献」 |
| 8 | 踢出需交叉验证 | 回显不含玩家名 |
| 9 | 破坏性操作二次确认（确认界面 + 人工） | 界面本身有警告，仍须人工签核 |
| 10 | 恢复动作不用 first_command | UI 模式不发聊天命令 |

## 十二、验收

- [ ] 入口链走通：hotbar 键 → 装扮与个人设定 → 公会物品 → 公会系统

- [ ] 按键试探生效：首键失败能改试候选键并缓存成功键
- [ ] 成员 tooltip 六字段全部解析正确
- [ ] 在线状态判定基于像素颜色，非 OCR 文本
- [ ] 公会详情取到「人数: [N/M]」中的 N
- [ ] 进入成员详情 → 升/降/踢物品可用；踢出经确认界面二次确认
- [ ] **升职/降职**用聊天回显「成功设置<玩家>的职位为<等级>!」验证成功
- [ ] **踢出**用「格位消失 / 数量对账 / 时间窗」中至少一种交叉验证，不得单凭「踢出成功」归因
- [ ] 权限不足提示被识别为失败并告警
- [ ] 组队钻石等无关物品被正确排除
- [ ] 屏蔽词玩家数据完整读取；缺失字段标「不可读」而非 0
- [ ] 三种材质包下（原版/第三方/服务器）定位均成功
- [ ] 代码中不存在任何图标模板文件或像素模板匹配路径（审查确认）
