# GUI 设计规范（tauri 版）

> 本文档与 `plan.txt` 阶段 3 同等效力；两者冲突时以本文档为准。
> 2026-10-30 起取代原 tkinter 方案（原方案实测观感有硬天花板：经典控件、无主题体系、
> 无 DPI 感知、按钮只能放客户区）。

---

## 一、定位与不可协商的约束

1. GUI **只承担配置与启停**，不参与 OCR / 按键 / 决策主链路。
2. GUI 是**独立进程**，与 Python 核经本地 IPC 通信；核心流程不得依赖 GUI 存在。
3. **GUI 只构建一份**，4 个含 `gui` 的能力变体共用；变体差异（代号、能力清单）
   由核在握手时下发，GUI 不得自己猜能力，也不得为每个变体单独编译。
4. 视觉目标：**现代桌面应用**，而不是"能用的配置表单"。
5. 所有界面文案为中文；技术标识（能力名、变体拼接名）保持英文原样。

## 二、架构与 IPC

### 2.1 进程与连接

```
布吉岛公会管理脚本-<变体>.exe   (Python 核, 持有 IPC 服务端)
        │  命名管道 \\.\pipe\bujidao-<token>
        ▼
布吉岛公会管理脚本-Gui.exe      (tauri: Rust 主进程 + WebView2 前端)
```

- 核启动时生成一次性随机 `token`（8 字节 hex）写入管道名，并把 token 与管道名
  通过命令行参数交给 GUI。**固定管道名一律不用** —— 防本机其它进程连上来。
- 消息格式：**单行 JSON**（UTF-8，无 BOM），一问一答带 `id`，事件推送不带 `id`。
- 崩溃处理：GUI 断开时核**继续运行**（只记 warning）；核退出时 GUI 提示
  "核心已退出"并关闭，不得静默留一个空壳窗口。

### 2.2 消息类型

| 方向 | method | 载荷 | 说明 |
|---|---|---|---|
| core→gui | `hello` | `{variant, capabilities[], plugin_version, config_schema_version}` | 握手，决定哪些功能可见 |
| core→gui | `config` | `{values{}, comments{}, readonly[]}` | 全量配置 + 中文注释 + 只读字段 |
| core→gui | `rules` | `{rules[]}` | 规则列表（阶段 4 数据） |
| core→gui | `state` | `{state: idle\|running\|paused\|failed, stage, done, total, player}` | 状态与进度 |
| core→gui | `event` | `{level:1-6, category, player?, text, ts}` | 单条事件 |
| core→gui | `events` | `{items:[event...]}` | 批量事件（节流用） |
| core→gui | `config_errors` | `{fields:{name:msg}}` | 校验失败，前端标红 |
| gui→core | `save_config` | `{values{}}` | 保存；核校验后回 `result` |
| gui→core | `start` / `pause` / `resume` / `stop` | `{}` | 运行控制 |
| gui→core | `save_rules` | `{rules[]}` | 保存规则，核做语法校验 |
| gui→core | `preview_rule` | `{rule, sample{}}` | 预览，**必须调用生产同一个求值函数** |
| gui→core | `open_reports` | `{}` | 打开报告目录（核执行，GUI 不碰文件系统） |
| gui→core | `window` | `{mode: normal\|compact, on_top: bool}` | 窗口状态同步给核（用于配置记忆） |
| gui→core | `check_update` | `{}` | 手动检查更新 |
| both | `result` | `{id, ok, error?}` | 应答；`error` 为**原样错误文本**，不得吞掉 |

### 2.3 事件类别（与日志 11 类关键事件对齐）

`start` 启动 · `config` 配置 · `window` 窗口与 OCR · `send` 发送 · `parse` 解析 ·
`async` 异步 · `pause` 暂停 · `decision` 决策 · `action` 执行 · `report` 报告 · `exit` 退出

前端按类别着色，`action` 与 `decision` 默认高亮，`exit` 单独置顶显示。

## 三、窗口

| 项 | 规格 |
|---|---|
| 默认尺寸 | **1000×680**（可自由缩放，不得默认最大化） |
| 最小尺寸 | **900×620**，小于此值时布局进入紧凑排版而非挤坏 |
| 位置记忆 | 记住上次位置与大小；若上次位置已在屏幕外（换显示器/拔扩展屏），回落居中 |
| 高 DPI | 必须声明 per-monitor DPI 感知；**100%→150% 缩放下不得模糊、不得错位** |
| 图标 | 任务栏与窗口图标一致，用 `gui/src-tauri/icons/` |

### 3.1 两套标题栏（`ui.custom_titlebar`）

**A. 自绘（默认 `true`）**

```
┌──────────────────────────────────────────────────────────┐
│ ▣ 布吉岛公会管理脚本 · Lite-Async-Gui-Vision(Q)  ⤡ 📌 ─ ✕ │ ← 标题栏 36px
├──────────────────────────────────────────────────────────┤
│  正文                                                    │
└──────────────────────────────────────────────────────────┘
```

- 高度 36px；左侧图标 + 标题 + **只读构建代号**；右侧自左往右：小窗 `⤡`、置顶 `📌`、
  最小化 `─`、关闭 `✕`
- 拖动：整条标题栏可拖（按钮区域除外）；**双击标题栏最大化/还原**
- 边缘缩放：四边 + 四角，热区 ≥4px
- 关闭按钮遵循托盘策略（见五）
- 无边框下必须处理：任务栏图标、Alt+Tab 预览、窗口阴影（DWM）

**B. 原生（`ui.custom_titlebar=false`）**

- 保留系统标题栏；系统按钮（最小化/最大化/关闭）由系统提供
- 小窗 `⤡` 与置顶 `📌` 放在标题栏下方一条 **32px 工具条**内，右对齐
- 工具条与正文之间用 1px 分割线，不使用第二种分隔样式

**两套共同要求**：切换后窗口尺寸/位置/置顶状态**不得丢失**；两套都要有快照测试。

### 3.2 小窗模式（`ui.start_mode=compact` 或点 `⤡`）

尺寸 **360×150**，只显示：

```
● 运行中 · 查询成员 87/200 · 当前 张三
────────────────────────────────────────
[████████████░░░░░░]  43%
[18:42:07] 已发送 /guild member 张三
```

- 必须包含：状态点 + 当前阶段 + 进度 n/N + **正在处理的玩家名** + 进度条 + 最新一条事件
- 本模式下正文页签、底部按钮一律隐藏（原 tkinter 版只隐藏 body 属未达标）
- 双击正文区域回到正常模式；`⤡` 按钮图标随模式切换方向

### 3.3 主界面信息架构（原则：**能显示的都显示**，不靠控制台补信息）

**运行**（默认页签）
- 状态卡：状态点（空闲/运行中/已暂停/失败）+ 当前阶段 + 进度 `n/N` + 进度条 +
  已用时 + **当前正在处理的玩家**
- 当前动作行：正在发送的命令原文 / 正在验证的对象 / 重试次数 / 上次结果
- **玩家表**（实时，随查询进度增量更新）：序号 · 玩家名 · 等级 · 周贡献 ·
  7 日明细 · 上次在线 · 在线状态 · 决策（升/降/踢/无操作）· 执行状态 · 备注
  —— 支持排序、筛选（按决策/等级/状态）、按名字搜索；屏蔽词玩家按原样显示 `***`
  并在备注标注「名称被屏蔽，指令不可查」
- **待办队列**（`pending_actions`）：玩家 · 动作 · 入队原因 · 入队时间 · 已重试次数
- **失败与跳过**：按类别分组（查询失败 / 执行失败 / 黑名单 / 白名单外 / 保护名单 /
  屏蔽词），每条带原因原文
- 运行控制：开始 / 暂停 / 继续 / 停止（**停止需二次确认**，提示未完成任务数）
- 报告入口：本次三份报告路径 + 「打开目录」按钮（核侧执行，GUI 不碰文件系统）

**配置**：与原 `config_panel` 全部配置项一一对应（人员 / 路径 / 窗口与按键 / 查询范围 /
阈值 9 项 / 延迟 6 项 / 超时 6 项 / 开关 6 项 / 阶段确认 / 黑白名单 / 屏蔽词策略 /
操作模式 / 按键试探 / 自动暂停 / 构建变体（**只读**）/ 界面检测 / 命令模板 5 /
文案模板 5 / 等级名 7 / 输出 / 错误关键词 / Debug / 异步 / 日志 / 主题 / 托盘 / 更新）；
不合法项标红并给文案

**规则**：行编辑（AND/OR 最多两层）↔ JSON 双视图、启用/禁用、排序、实时预览

**日志**：事件流（分级 / 类别着色 / 搜索 / 复制 / 暂停滚动 / 打开报告目录）

**关于**：版本 · 构建变体与能力清单 · 更新检查 · 日志目录 · 报告目录

**底部状态条**（常驻）：托盘状态 · 配置是否已保存（有未保存改动时高亮）· 待办数 ·
失败数 · 当前日志级别

### 3.4 确认与暂停交互（原先靠控制台 input，GUI 必须完整接管）

| 场景 | 要求 |
|---|---|
| **阶段确认点** | 弹模态确认卡：即将进入哪一阶段、目标人数、预计动作数；按钮「继续 / 暂停 / 停止」。粒度按配置开关。**不得只留控制台等待** |
| **kick 二次确认** | 模态：显示玩家名 + 当前等级 + 周贡献，要求输入确认词（默认取 `ui.kick_confirm_text`）；方式可配（弹窗 / 主界面） |
| **启动倒计时** | 3 秒倒计时在界面内大号数字可视，文案「请不要操作键盘和鼠标」 |
| **暂停** | 点暂停或按暂停键 → 立即停止发送与点击；状态转「已暂停」；显示暂停原因（手动 / 检测到用户键鼠活动 / 阶段确认中） |
| **继续** | 仅暂停键或 GUI「继续」按钮可解除；继续后显示「正在重置窗口…」，由核完成激活→Esc→界面确认 |
| **自动暂停（UI 模式）** | 状态卡显示「已暂停：检测到你的键鼠操作」，并提示按暂停键继续 |

### 3.5 配置页启动行为与热重载（**对齐原始要求，纠正当前偏离**）

现状偏离：配置页首次启动时是空的、也不自动切过去（残留 CLI 血统）。按原始要求纠正为：

- **启动即生成 + 自动落页**：`config.json` 不存在时立即用默认值生成（JSONC + 中文注释），
  并**自动切到「配置」页签**；生成失败必须显式报错，不得显示空白窗体。
- **首次硬门禁（仅"启动时无配置文件"这一种情况）**：
  用户**必须做出修改并保存**，才允许切换到其它页签；
  保存后提示「配置已保存，请重新启动脚本」。
  已有配置文件时**不设门禁**：直接加载 → 可修改并保存 → 点「开始运行」进入主流程。
- **配置页不得为空**：始终渲染 `DEFAULT_CONFIG` 全部键（当前 126 项），
  无用户值时显示默认值，绝不出现空白面板。
- **热重载（GUI 模式）**：保存后立即生效的项 —— 主题、标题栏样式、托盘策略、
  窗口尺寸/置顶、阈值/延迟/超时/开关/名单/文案、日志级别；
  **必须重启**的项 —— `operation_mode`、`async.enabled`、GUI 管道/端口、日志目录。
  需重启项在界面打「需重启」标记，保存后提示「有 N 项需重启生效」并给「立即重启」入口，
  禁止静默地"改了没生效"。

### 3.6 按键绑定控件（键位捕获）

适用于所有按键类配置（聊天栏键、暂停键、候选键列表等）：

1. 控件形态：`当前键：key.keyboard.x` + 「绑定」+ 「清除」。
2. 点「绑定」→ 进入**捕获模式**，界面显示「请按下要绑定的按键…（Esc 取消）」，
   并在 GUI 进程内启动**全局键盘钩子**。
3. 捕获期间**吞掉按键**（不向其它窗口透传），避免误触发游戏。
4. 按下任意键盘键/鼠标键 → 记录 → **立即关闭钩子** → 写回配置（标记未保存改动）。
5. **Esc = 取消并关闭钩子**，不写入；这是唯一取消键，不得用其它键取消。
6. 超时 10 秒无输入自动取消并关闭钩子，提示「未捕获到按键」。
7. 键名规范化：统一 `key.keyboard.<name>` / `key.mouse.<n>`（与 options.txt 一致，
   字母小写）；显示时给人类可读形式（`X`、`鼠标左键`、`F7`）。
8. 冲突提示：与其它配置项重复时提示，但不阻止保存。
9. 钩子失败（无权限/被占用）→ 明确报错并保持原值，**禁止静默不生效**。
10. 测试：键名解析/规范化/冲突检测为纯逻辑，必须有单测；钩子层用 mock 覆盖
    「开启 → 捕获 → 关闭」「取消 → 关闭」「超时 → 关闭」三条路径。

状态色不得用于非语义场景（装饰）。

### 4.2 尺度

| 项 | 值 |
|---|---|
| 基础间距单位 | 4px；常用 8 / 12 / 16 / 24 |
| 圆角 | 卡片 8px；按钮 6px；输入框 6px；小窗 10px |
| 字号 | 标题 15px / 正文 13px / 说明 12px / 等宽（日志、JSON）12px |
| 行高 | 正文 1.6；日志 1.5 |
| 控件高度 | 按钮/输入框 28px；页签 32px |
| 阴影 | 仅浮层（对话框、下拉）使用，卡片不用阴影 |
| 动效 | 120–180ms，ease-out；**禁止弹跳、旋转等装饰性动画** |

### 4.3 布局

- 顶部：标题栏（或原生栏 + 工具条）
- 中部：左侧页签（配置 / 规则 / 日志 / 关于），右侧内容区；页签宽 148px
- 底部：状态条（左：状态与进度；右：保存 / 开始运行 / 停止）
- 配置项统一形态：`标签（右对齐，宽 160px） + 控件 + 说明（12px，text-dim）`
- 错误态：控件描边 `danger` + 下方 12px 错误文案；**不得只变色不给文案**
- 长列表一律虚拟滚动；空状态必须给一句说明，不留空白面板

### 4.4 图标（**统一用 SVG**，禁 emoji 与字符字形）

- 位置：`gui/src/icons/`，以组件方式内联引用；**不得远程加载**、不得用位图
  （应用 logo 除外）。
- 画布 24px / 视觉 16px，描边 1.5px，`stroke="currentColor"`、`fill="none"`；
  置顶激活态例外（`fill="currentColor"`）。随主题自动变色，不得写死颜色。
- **禁用**：emoji（`📌`）、字符字形（`⤡`）、彩色图标。
- 四个必备图标（形制参照 `D:\Test\Dev\wyz-cjjmjj-dev\fix\ex\` 的四张参考图）：

| 图标 | 语义 | 形制 | 状态色 |
|---|---|---|---|
| `icon-compact.svg` | 切到小窗 | 双矩形（一大一小）+ 指向右下的箭头 | `text-dim`，hover 用 `text` |
| `icon-expand.svg` | 回到正常尺寸 | 双矩形 + 指向左上的箭头 | 同上 |
| `icon-pin-filled.svg` | 已置顶 | **实心**图钉 | `accent` |
| `icon-pin-outline.svg` | 未置顶 | **描边**图钉 | `text-dim` |

- 其余界面图标（播放/暂停/停止/刷新/搜索/文件夹/复制）同样用 SVG 线性图标，
  同一套描边与圆角，不得混入不同风格的一套。

## 五、托盘

| 项 | 规格 |
|---|---|
| 配置 | `ui.tray.enabled`（默认 true）、`ui.tray.close_action = ask\|minimize\|exit`（默认 ask）、`ui.tray.ask_on_close`（默认 true） |
| 首次关窗 | 弹一次对话框：「关闭时希望怎么做？」①最小化到托盘 ②直接退出，附复选框「不再询问」 |
| 勾选不再询问 | 写入 `close_action`，`ask_on_close=false`；设置页可改回「每次询问」 |
| 托盘图标四态 | 空闲（灰）· 运行中（accent）· 已暂停（warn）· 有失败（danger，带角标计数） |
| 托盘菜单 | 显示窗口 / 暂停 / 继续 / 退出（退出是真退出，不走 `close_action`） |
| 运行中点关闭 | **不得直接退出**：先暂停 → 提示「还有 N 个任务未完成验证，退出将丢弃」，由用户选择 |
| 系统关机/注销 | 不弹窗，直接安全退出并记日志 |
| `tray.enabled=false` | 点关闭直接退出，不询问、不驻留 |

托盘提示文案只显示状态与进度（如「运行中 · 87/200」），**不得显示玩家名**（防截图外泄）。

---

## 六、实时事件流

1. **GUI 不读日志文件**。所有显示内容都来自核推送的结构化事件。
2. **节流**：核侧每 ~100ms 批量推送一次（`events`）；单批超过 500 条时折叠为
   「N 条同类事件」摘要行，原文可展开。GUI 侧环形缓冲 **2000 条**，超出丢弃最旧。
3. **分级**：默认只显示 4 级以上（信息/调试/追踪按需开启）；trace 开启时界面必须
   给出明确提示（避免误以为卡死）。
4. **类别着色**：`send` 蓝、`parse` 青、`async` 紫、`pause` 黄、`action` 橙、
   `exit` 红；其余中性色。颜色取自 token，不新增色值。
5. **点击定位**：点某条事件，若带 `player` 则右侧详情栏显示该玩家本次的判定链
   （阈值/规则 + 输入值 + 结论）。
6. 日志面板只读；提供「复制本条」「暂停滚动」「打开报告目录」三项操作。

---

## 七、规则编辑器

1. **一套数据两个视图**，同一份 `rules[]`。
2. 行编辑视图：每行 = 启用开关 + 规则名 + 条件组 + 动作 + 优先级 + 删除。
   条件组支持 AND/OR，**最多两层**；字段下拉取自引擎支持的字段枚举
   （周贡献 / 当前等级 / 加入时间 / 上次在线 / 在线状态 / 玩家名匹配），
   操作符与值类型随字段变化（数值 / 时间 / 枚举 / 正则）。
3. JSON 视图：与行编辑双向同步。JSON 中出现可视化表达不了的结构（三层以上嵌套、
   复杂组合），行编辑侧**只读置灰并显示原因**，绝不静默丢弃。
4. **预览必须调用生产的同一个求值函数**（经 IPC `preview_rule`），禁止前端自行判断。
   预览输入用合成玩家样本，不得使用真实玩家名（纪律第 6 条）。
5. 拖拽排序只作为「优先级数字」的另一种编辑方式，拖完必须回写数字；数字与顺序
   不一致时以数字为准并提示用户。
6. 未保存改动：切页拦截、关闭窗口拦截、托盘退出前拦截，三处都要提示。
7. 删除/禁用提供一次撤销。

## 八、自动更新

| 档位 | 行为 | 默认 |
|---|---|---|
| `check` | 启动后后台查一次，有新版本在「关于」页与托盘提示 | — |
| `notify` | 弹窗显示版本号与变更摘要，用户点「更新」才下载安装 | ✅ 默认 |
| `auto` | 静默下载并安装，退出后生效 | ❌ 默认关 |

**硬拦截（任何档位都生效）**：
- 运行中（`state=running`）禁止发起安装
- 存在未完成待办（`pending_actions.json` 非空）禁止发起安装
- 更新失败必须回落到旧版可用状态并记日志（禁止半更新目录）

**更新必须走安装器**：下载的是 MSI/NSIS 安装包，由安装器完成"退出→替换→注册表版本号更新"
（`DisplayVersion`、`EstimatedSize`、`InstallDate`）。**禁止只替换 exe** —— 那会让
Windows「应用和功能」里显示的版本与实际不一致，也会让第三方卸载工具判断错版本。

`latest.json` 按变体分列，GUI 用自己的拼接名匹配：

```json
{ "version": "1.0.2",
  "variants": {
    "Lite-Async-Gui-Vision": { "url": "…(Full).zip", "sha256": "…", "signature": "…" },
    "Lite-Gui":               { "url": "…-Lite-Gui.zip", "sha256": "…" }
  }}
```

签名校验必须开启；无签名的清单视为无效，直接报错，不提供「忽略」选项。

## 九、发布形态与体积

| 产物 | 说明 |
|---|---|
| `布吉岛公会管理脚本-<拼接名>.exe` | 核，**唯一入口**；gui 变体需同目录的 `Gui.exe` |
| `Gui.exe` | 界面进程，**4 个含 gui 的变体共用一份** |
| `布吉岛公会管理脚本-<拼接名>.zip` | 便携绿色版：核 exe + Gui.exe（gui 变体）+「启动.cmd」+ 说明；无卸载项 |
| `布吉岛公会管理脚本-<拼接名>.msi` | 安装包：装上述文件 + 卸载程序 + 注册表卸载项（§9.1）；快捷方式指向核 exe |
| `latest.json` | 自动更新清单，按变体分列 |

**入口唯一性**：用户可见的启动入口只有一个（快捷方式/启动.cmd 都指向核 exe）；
`Gui.exe` 是核拉起的内部组件，不单独提供快捷方式。

**入口规则**：
- 非 gui 变体：单文件，纯 CLI。
- gui 变体：安装目录两个文件 —— 核 exe（`布吉岛公会管理脚本-<拼接名>.exe`）+ `Gui.exe`。
  **`Gui.exe` 由 4 个含 gui 的变体共用一份**，不得复制成 4 份。
- **用户只看到 1 个入口**：开始菜单与桌面快捷方式都指向核 exe；
  配置 `ui.enabled=true` 时核启动即拉起同目录 `Gui.exe`，不需要 `--ui`
  （`--ui` 仅用于强制覆盖配置）；找不到 `Gui.exe` 必须明确报错并回落纯 CLI，
  不得静默无界面。
- 便携 zip：两个文件放同一目录 + 一个「启动.cmd」指向核 exe，避免用户点错。

### 9.1 安装、卸载与注册表契约（必须能被系统"应用和功能"识别）

- 安装包用 **NSIS 或 MSI**（tauri bundler 内置），**必须生成独立卸载程序**
  （NSIS 生成 `uninstall.exe`；MSI 走 `msiexec /x {GUID}`），并在开始菜单提供「卸载」。
- 必须在注册表写入卸载项，否则第三方卸载工具与 Windows「应用和功能」看不到：
  `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\<GUID>`（按需 32/64 视图）
  至少包含：`DisplayName`（含变体代号）、`DisplayVersion`、`Publisher`、
  `DisplayIcon`（指向安装目录 exe）、`InstallLocation`、`UninstallString`、
  `QuietUninstallString`、`EstimatedSize`（KB）、`NoModify=1`、`NoRepair=1`、
  `InstallDate`（YYYYMMDD）。
- 卸载必须**完整且可重复执行**：删除安装目录、开始菜单项、注册表卸载项、
  `%LOCALAPPDATA%` 下解包出的核 exe 与用户缓存；用户数据（config.json、reports、logs）
  默认保留，卸载时询问一次「是否一并删除配置与报告」。
- **更新必须走安装器**（见 §8），由安装器改写注册表 `DisplayVersion` 与 `EstimatedSize`；
  禁止只替换 exe——那会让系统里的版本号与实际不一致。

- 全能力变体的文件名追加 `-Full` 后缀，如
  `布吉岛公会管理脚本-Lite-Async-Gui-Vision-Full.zip`；**拼接名必须保留在文件名中**。
  后缀只用连字符形式，**禁用括号 `(Full)`**（未加引号时是 cmd/PowerShell 的语法陷阱，
  且 artifact 名会被 URL 编码成 `%28/%29`）。
- 体积预算：GUI 单独 ≤ 15MB（自包含 tauri）；核体积不得因 GUI 变化。
  **实测值必须写进体积记录节**，不接受估算。

## 十、构建与 CI

1. GUI 构建一次（cargo/tauri），产物复制进 4 个含 gui 变体的 artifact。
2. CI 需缓存 Rust 工具链与 `target/`，避免每次全量编译。
3. 冒烟：GUI 必须真正启动一次并退出（`--smoke-test` 参数，2 秒后自关），
   **不接受"进程能起来就算过"**；核与 GUI 的 IPC 握手要在冒烟里验证。
4. 快照测试：深浅两套主题 × 两种标题栏 = 4 组基准图，像素差异阈值 ≤0.1%。
5. 文档同步：本文件、`docs/使用说明.md`、`docs/配置说明.md`、`docs/流程与架构图.md`
   必须同一轮更新。
