## 二、硬件交互层（mock 覆盖 + mock 策略）

> 验收标准原文：
> 「【硬件交互层:mock 覆盖 + 单独报告】pyautogui 按键模拟、winsdk OCR、文件轮询 ——
> 以 mock 覆盖分支逻辑与异常路径,**真实设备调用不计入分母**;覆盖率与 mock 策略单独成节报告」

### 覆盖现状（不并入核心层分母，单独记录）

| 模块 | 职责 | 覆盖率 |
|---|---|---|
| `infrastructure/window_input.py` | 窗口查找/置前 + 键名解析 + 模拟人工输入 | 99% |
| `infrastructure/game_state.py` | OCR 界面状态检测（菜单/聊天栏） | 100% |
| `infrastructure/log_watcher.py` | 日志增量监控 + 编码检测 + 响应块提取 | 100% |
| `infrastructure/logger.py` | 6 级分级日志 + 归档 | 100% |
| `vision/`（阶段 6） | 键位解析/扫掠/导航/验证（截图与 OCR 均可注入） | 由 `tests/test_vision_*` 124 用例覆盖 |

### mock 策略（铁律）

| 依赖 | 处理方式 | 为什么 |
|---|---|---|
| `pyautogui.press/hotkey/write` | `unittest.mock.patch` 成记录调用的假函数 | 绝不真实按键——测试跑一次就会真去按键盘 |
| `pyautogui.screenshot` | 注入伪造 Image 对象（`_FakeImage`，返回假 PNG 字节） | 绝不真实截屏 |
| `winsdk.windows.media.ocr.OcrEngine` | 注入伪造 engine，`try_create_from_language` 返回可控 engine 或 None | 绝不调系统 OCR；None 路径专门验证**降级** |
| 外部 OCR 命令（`vision.ocr_command`） | 替换为返回固定文本的假函数 | 不依赖本机是否安装 OCR |
| `pyperclip.copy` | patch + 可控抛异常 | 验证剪贴板被占用时的重试与重试耗尽 |
| `LogWatcher` 的日志文件 | 一律 `tempfile.mkdtemp()` 下的临时文件 | 绝不读真实 `latest.log` |
| `time.sleep` | patch 成 no-op；**通过断言调用参数**验证等待时长取值正确 | 测试秒级完成，且仍验证"等了多久" |
| `ctypes` 窗口操作（`user32.*`） | 通过注入 `hwnd=None` / mock 对象绕过 | 不碰真实窗口句柄 |

### 为什么"真实设备调用不计入分母"

硬件行为（真实按键延迟、OCR 实际识别率、Windows 焦点策略）不可在 CI 环境复现，
且不可重复。把它们计入覆盖率会产生**虚假分数**：跑一次绿、下次因为焦点被抢而红。
所以策略是——**分支逻辑与异常路径用 mock 确定性覆盖**，真实设备行为由人工在
真机验收（不属于 CI 门禁的一部分）。

### 专门覆盖的硬件层业务点

- **OCR 误判防护**（验收第 8 条）：关键词归一化、多帧采样去抖、二次确认、缓存复用、
  OCR 不可用时**报错而不是静默降级**（UI 模式）/ 试探式发送（指令模式）
- **编码检测**：utf-8 / gbk / gb2312 及全失败回退；多处采样防"开头纯 ASCII 误判 utf-8"
- **文件轮转**：`latest.log` 被重建/截断时重新打开
- **`discard_buffer`**：first_command 前丢弃残留，防把上次回显当本次响应
- **暂停门**：暂停期间发送线程阻塞，**零指令发出**（解除暂停后才发）
- **发送互斥**：多线程下模拟输入串行化（最大并发=1，否则剪贴板会串）
- **踢出交叉验证**：回显不含玩家名，必须用格位消失 / 人数对账 / 时间窗之一佐证

## 四、测试有效性保障

- **回归锁定**：每个审查发现的缺陷都带一个能在修复前失败的用例（如
  `test_disabled_switch_blocks_resume_of_that_action`、`test_non_empty_rules_survive_form_save`）。
- **变异验证惯例**：关键修复会把 bug 临时注入回去确认测试变红，再还原（不提交注入版本）。
- **门禁双重保险**：CI 的 Gate 1（核心 98%）与 Gate 2（总体 92%）分别独立跑，
  任一不过则 job 失败；本地命令与 CI 完全一致。
- **稳定性**：Tk 相关用例在运行时不可用时会 `SkipTest`（`make_root` / `app_or_skip`），
  不让环境问题把覆盖率门禁染红。
